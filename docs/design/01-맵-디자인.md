# Recoil Crew — Seeded Map Generation System (기준 스펙)

> **작성:** 2026-08-03 · **상태:** 채택 (기준 스펙)
> **근거:** 외부 검토본 "Robust Seeded Map Generation System"을 기준으로 채택. 48시간 제약 없음.
> **채택 시 수정사항:** ① 트럭(truckRoute) 완전 제외 ② 몬스터 AI 패스파인딩은 이 문서의 범위 밖 (추후 별도 교체 예정)
> **상위 결정:** 맵 크기 400×400 · 의사 절차적 생성 (메가봉크 방식) · 결정적 시드

---

## 1. 개요

메가봉크식 의사 절차적 생성의 완전한 구현. 매판 유니크하면서 규칙이 있는 맵을 **결정적으로** 생성한다.

**요구사항:**
- **결정적** — 같은 시드 = 항상 같은 맵 (서버/클라 동기화, 테스트 재현)
- **검증 가능** — 생성 결과가 규칙을 위반하면 폐기하고 재생성
- **현재 엔진 호환** — 시뮬레이션 코드(`match.ts`)가 참조하는 인터페이스 유지
- **렌더러 무관** — 생성 결과는 데이터(배열/그리드)로만 표현
- **확장 가능** — 바이옴/난이도 프로파일을 JSON 데이터로 추가
- **저비용** — 생성은 런 시작 시 1회, 결정적이라 캐시 가능

---

## 2. 현재 엔진과의 관계

| 현재 (`arena.ts`) | 생성 시스템 도입 후 |
|---|---|
| 하드코딩 `ARENA` 상수 (obstacles/ramps/barrels/spawnPoints) | `buildArena(seed, profile)` 함수의 산출물 |
| `obstacleAt()` / `groundHeightAt()` / `resolveCircle()` | **시그니처 유지** — 호출부 무수정 |
| 클라·서버가 같은 상수 import | 서버가 생성 → 체크섬 전파 → 클라가 동일 생성 (결정적) |

---

## 3. 아키텍처 — 4계층 생성 파이프라인

```
Layer 0: 프롤로그/시드 — 시드 포뮬라, PRNG 초기화
Layer 1: 지형 — heightfield + 매크로 피처 (언덕/계곡/능선/고원/분지)
Layer 2: 경로 그래프 — 웨이포인트/이동 경로/게이트 배치
Layer 3: 퍼니처/콘텐츠 — 장애물·배럴·크레이트·램프·스폰 포인트
```

각 레이어는 **독립된 PRNG 서브스트림**을 사용한다 → 특정 레이어의 변경이 다른 레이어 결과에 영향을 주지 않는다.

---

## 4. 시드

### 4.1 시드 포뮬라

```
seed = hash(roomCode) ⊕ matchIndex ⊕ profileId ⊕ version ⊕ attempt
```

| 구성요소 | 의미 |
|---|---|
| `roomCode` | 방 식별자 (고정) |
| `matchIndex` | 리매치 횟수 → 매판 다른 맵 보장 |
| `profileId` | 맵 프로파일 (바이옴/난이도) |
| `version` | 생성 규칙 버전 — 규칙 수정 시 구버전 맵과의 호환 단절 |
| `attempt` | 검증 실패 시 재시도 카운터 (+1) |

### 4.2 버전 관리

- 생성 규칙(레이어 로직)이 바뀌면 `version`을 올린다
- 체크섬·시드가 version에 묶이므로, 버전 불일치 시 즉시 감지

---

## 5. 결정적 PRNG

- **mulberry32** (32비트 시드) 또는 **splitmix32** 계열 사용
- 모든 난수는 PRNG에서만 생성 — `Math.random()` 금지
- **서브스트림(fork):** 레이어마다 `fork(seed, "terrain")`, `fork(seed, "routes")`처럼 이름 기반 분기
  - 퍼니처 배치 로직을 바꿔도 지형 생성 결과는 동일하게 유지됨

---

## 6. Heightfield (지형 높이맵)

- **표현:** `Float32Array` 그리드 (N×N 셀, 셀 크기 ~4m → 400×400 = 100×100 셀)
- **높이 범위:** -5m ~ +10m (경사는 단계별 제한)
- **경사 제한:** 모든 셀 간 높이 차를 클램프 — 탱크가 오를 수 있는 최대 경사 보장
- **쿼리:** `groundHeightAt(x, z)`가 heightfield 기반으로 동작 (기존 인터페이스 유지)

---

## 7. 매크로 피처 (지형의 뼈대)

heightfield 위에 **규칙 기반 피처**를 그린다 (메가봉크의 "분포 있는 랜덤"):

| 피처 | 파라미터 예 | 역할 |
|---|---|---|
| **분지 (Basin)** | 반경, 깊이 | 중앙 결전지 — 낮은 지대, 사방 유입 |
| **능선 (Ridge)** | 길이, 방향, 높이 | 맵 분할, 시야 차단 |
| **고원 (Plateau)** | 반경, 높이, 경사 | 고지대 진입 보상 (반동 이동의 무대) |
| **계곡 (Valley)** | 폭, 깊이, 방향 | 자연 통로 — 호드/플레이어 이동 축 |
| **언덕 (Hill)** | 반경, 높이 | 국지적 고저차, 엄폐 |

**규칙:**
- 피처 간 최소 이격 (겹침 금지)
- 피처 수/크기는 프로파일이 정의 (바이옴별 분포 차별)
- 모든 피처는 heightfield에 **가산(blend)** — 셀 단위로 결정적

---

## 8. 경로 그래프

플레이어/호드/게이트가 쓰는 **이동 축**을 생성한다:

1. **웨이포인트 후보 생성** — 중요 지점 (중앙, 구역 중심, 게이트 후보)
2. **Delaunay 삼각분할** → 후보 간 연결 후보
3. **MST(최소 신장 트리)** 로 최소 연결 보장 + 추가 간선으로 순환 확보
4. **경로 검증:**
   - 경사: 모든 경로 구간이 탱크 주행 가능 경사 이내
   - 폭: 경로 최소 폭 확보 (장애물이 경로를 막지 않게)
5. 결과: **게이트 위치 + 호드 이동 경로 + 플레이어 권장 동선**이 이 그래프에서 파생

---

## 9. 퍼니처 배치 (Layer 3)

지형/경로 확정 후 배치:

| 항목 | 규칙 |
|---|---|
| 장애물 | 경로 그래프 밖 배치, 경로 폭 침범 금지 |
| 배럴 | 최소 이격 (연쇄 폭발 전맵 번짐 방지), 경로와 거리 유지 |
| 램프/플랫폼 | 고원/계곡 접근용 — 경사 제한 내, 착지 안전 |
| 크레이트(업그레이드) | 매크로 피처 위주 배치 (고지대/위험지대 = 고급) — 분포는 프로파일 |
| 스폰 포인트 | 중앙 근처, 클리어런스 확보 |

---

## 10. 의미론적 구역 (Semantic Zones)

생성 후 heightfield/피처를 분석해 **구역 레이블**을 붙인다:

- `flat` / `slope` / `highland` / `valley` / `basin`
- 용도: ① 스폰·게이트·퍼니처 배치 제약 ② 미니맵/랜드마크 생성 ③ 추후 게임플레이(구역 효과) 연결 지점
- 데이터로 저장 (렌더링/게임플레이에서 참조)

---

## 11. 스폰 포인트 & 게이트

- **플레이어 스폰:** 중앙 분지 근처 3~4곳, 서로 충분한 이격 + 클리어런스
- **호드 게이트:** 경로 그래프의 끝단 (맵 가장자리) 6~8곳 — 경로를 따라 중앙으로 유입
- 모든 스폰/게이트는 검증 항목에 포함

---

## 12. 검증 시스템 (Validation)

생성 완료 후 **전체 검증** 실행. 실패 항목이 있으면 `attempt++`로 재생성:

| 범주 | 검증 항목 |
|---|---|
| **셀/지형** | 경사 한계 내 · 높이 범위 내 · 피처 겹침 없음 |
| **경로** | 경로 연속성 · 경사 한계 · 최소 폭 · 게이트 연결 |
| **스폰** | 스폰 클리어런스 · 게이트 클리어런스 · 서로 이격 |
| **퍼니처** | 배럴 이격 · 경로 비침범 · 램프 착지 안전 · 도달 가능성 (모든 지점 연결) |
| **전역** | 결정성(동일 시드 재생성 = 동일 결과) · 예산(오브젝트 수 상한) |

- 검증은 **순수 함수** — 유닛 테스트로 자체 검증
- 실패 시 최대 N회 재시도 (예: 8회) → 그래도 실패 시 **폴백 맵** (수작업 기본 맵)

---

## 13. 재시도 & 폴백

```
attempt 0..7 → 검증 실패 시 재생성
attempt = 8 → fallback: 수작업으로 검증된 기본 맵 사용 (게임은 항상 시작됨)
```

- 폴백 맵도 동일한 체크섬/시드 파이프라인에 태운다 (일관성)
- "게임이 시작되지 않는" 상태는 원천 차단

---

## 14. 체크섬 (동기화 안전망)

- 생성된 맵 데이터의 **체크섬**(해시)을 산출
- 서버가 맵 생성 → 체크섬을 클라이언트에 전송
- 클라이언트가 로컬 생성한 맵의 체크섬과 비교 → 불일치 시 **라운드 시작 거부** (desync 방지)
- 체크섬은 시드 + version + 생성 규칙 버전에 묶임

---

## 15. 프로파일 (데이터 드리븐)

맵 종류/바이옴/난이도는 **JSON 프로파일**로 정의:

```json
{
  "id": "basin_v1",
  "version": 1,
  "size": 400,
  "features": { "basin": 1, "ridges": 2, "plateaus": 3, "valleys": 2, "hills": 8 },
  "furniture": { "barrels": 30, "obstacles": 25, "crates": 14, "ramps": 6 },
  "zones": { "highlandCrateBonus": 2.0 },
  "spawns": { "player": 4, "gates": 7 }
}
```

- 새 바이옴 = 새 JSON 추가 (코드 변경 없음)
- 프로파일 id가 시드 포뮬라에 포함 → 프로파일별 독립 맵

---

## 16. 렌더링 & LOD

- **지형 메시:** heightfield에서 생성 (셀 단위 삼각형)
- **LOD:** 카메라 거리 기반 — 근거리 정밀 메시 / 원거리 저밀도 메시
- **컬링:** 카메라 밖 셀/퍼니처 드로우 제외
- **안개(fog):** 시야 100~150m — 원거리 로딩 부담 완화 + 큰 맵의 분위기
- **지면 텍스처:** 셀/구역 기반 타일링 (heightfield에 UV 매핑)

---

## 17. 네트워킹

- **서버:** `buildArena(seed)` 실행 → 체크섬 산출 → 스냅샷/입장 시 체크섬 + 시드 전송
- **클라이언트:** 동일 시드로 로컬 생성 → 체크섬 대조 → 불일치 시 에러 표시 후 재시도/거부
- 결정적 생성 덕에 **맵 데이터 자체는 전송하지 않는다** (시드 + version만)

---

## 18. 테스트 전략

| 테스트 | 내용 |
|---|---|
| **결정성** | 동일 시드 × 100회 생성 = 바이트 단위 동일 결과 |
| **규칙 위반** | 시드 스윕 10,000개 — 검증 실패율 기록 (0에 가까워야 함) |
| **폴백** | 검증 실패를 강제 → 폴백 맵 정상 동작 |
| **체크섬** | 시드/버전 변경 시 체크섬 변경 확인 |
| **퍼포먼스** | 생성 시간 상한 (예: < 500ms), 셀 수 × 오브젝트 수 상한 |
| **e2e** | 고정 시드로 실제 매치 플레이 (서버-클라 동기) |

## 19. 마일스톤

| 단계 | 내용 |
|---|---|
| **M1** | 시드 파이프라인 + heightfield + 매크로 피처 + 검증 + 폴백 + 체크섬 |
| **M2** | 경로 그래프 + 게이트 + 퍼니처 배치 + 구역 레이블 |

| **M4** | 시드 스윕 테스트 + 폴리싱 + 바이옴 프로파일 확장 |

## 20. 명시적 제외 (2026-08-03 채택 시 확정)

- ❌ **트럭(truckRoute)** — 완전 제외. 턴 반경·경로 검증 등 truck 관련 요구사항 없음
- ❌ **몬스터 AI 패스파인딩** — 현재 엔진의 추종 방식 유지. AI는 **별도 작업으로 추후 교체 예정** (이 문서의 범위 밖)
- ❌ **동굴/브리지/파괴 가능 지형** — M3 이후 별도 검토
- ✅ **유지:** 맵 크기 400×400 · pseudo-procedural 원칙 · 결정적 시드
